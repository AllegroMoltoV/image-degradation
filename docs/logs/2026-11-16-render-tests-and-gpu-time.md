# 統合テストと GPU 時間の記録

記録日: 2026-11-16

## はじめに

この文書は、JPEG の劣化のフィルターの最初の実装について、描画の統合テストの結果と、1920×1080 での GPU 時間を記録したものです。GPU 時間は、ガビガビ度の上限と既定値を依頼者が決める判断材料に使います。

## 検証環境

- CPU: Intel Core i7-11700F
- GPU: NVIDIA GeForce RTX 3060 Ti
- OS: Windows 11 Home 10.0.26300
- OBS: libobs 31.1.1 (`.deps` に取得したもの)。OBS Studio のアプリは起動していません。
- ビルド: RelWithDebInfo、コミット `aab94a7`

## 検証方法

統合テストは CTest に登録した 18 件です。D3D11 と OpenGL の 2 方式で、9 つのシナリオを実行しました。

```
ctest --test-dir build_x64 -C RelWithDebInfo
```

GPU 時間は `jpeg-crunch-benchmark` で D3D11 について測りました。1920×1080 の合成画像に対し、60 フレームの平均を 5 回測った中央値です。フィルターなしで同じソースを描く時間を基準とし、その差をフィルターの時間としました。

```
jpeg-crunch-benchmark <simple-jpeg-crunch.dll> <data> <libobs-d3d11.dll> <libobs の data> 1 16 44 100
```

ガビガビ度 1・16・44・100 は、保存し直しの回数がそれぞれ 1・2・4・8 回になる値です。

## 検証結果

### 統合テスト

18 件すべてが合格しました。出力の生ログは `.logs/2026111621-ctest.log` にあります。

CPU 参照と比べるシナリオの統計は次のとおりです。比較できる画素の割合は、丸めの境目からの余裕が `kTieEpsilon` (1e-5) 以上の画素の割合です。D3D11 と OpenGL で同じ値でした。

| シナリオ | ガビガビ度 | 回数 | 比較できる画素 | 不一致の画素 |
| --- | --- | --- | --- | --- |
| single | 10 | 1 | 100% | 0 |
| chain | 20 | 2 | 100% | 0 |
| max (記録のみ) | 100 | 8 | 100% | 0 |
| odd-size-single (61×45) | 10 | 1 | 100% | 0 |
| odd-size-chain (61×45) | 20 | 2 | 100% | 0 |

境目の幅を 1e-4 にしたときは、odd-size-chain で比較できる画素の割合が 90.7% に下がりました。max では 0% でした。いずれも不一致は 0 件でした (`.logs/2026111612-ctest-eps1e-4-verbose.log`)。

srgb16f では、同じ絵を SRGB と SRGB_16F の入力で処理した出力の平均の絶対差が、D3D11 と OpenGL の両方で 0 でした。

テストが誤りを検出できることを、わざと壊した実装で確かめました。入力を sRGB の符号化を解かずに読むよう変えると、single・chain・odd-size・srgb16f・settings-update の 5 つのシナリオが、両方の描画方式で失敗しました (`.logs/2026111616-ctest-mutant.log`)。

### GPU 時間 (1920×1080、D3D11)

| ガビガビ度 | 品質 | 回数 | 1 フレームの GPU 時間 (ms) |
| --- | --- | --- | --- |
| 1 | 90 | 1 | 0.517 |
| 16 | 77 | 2 | 0.876 |
| 44 | 53 | 4 | 1.695 |
| 100 | 5 | 8 | 3.345 |

基準のフィルターなしの時間は 0.026 ms でした。生ログは `.logs/2026111622-bench-d3d11.log` にあります。

## 考察

GPU 時間は回数にほぼ比例し、1 回あたり約 0.42 ms だと考えています。60 fps の 1 フレームは 16.7 ms です。最大の 8 回では、その 20% に当たる 3.3 ms を、このフィルター 1 つが使います。性能の低い GPU では、この数倍になると推測します。

CPU 参照との比較では、8 回を重ねても不一致がありませんでした。GPU と CPU の計算の差は、この GPU では 1e-5 より小さいと考えています。CI のソフトウェア描画では差が大きくなる可能性があり、その場合は不一致の画素の余裕のログを見て幅を広げます。
